# Ручная проверка редактора процессов

Что проверяем: редактор и каталог процессов из issue #40. Человек должен без кода и без чтения документации понять процесс, поменять его формой или словами, собрать свой, попробовать его и запустить вручную или автоматизацией. Автотесты (`pnpm test`) проверяют логику. Здесь проверяется то, чего они не видят: понятность, тексты, вид в обеих темах, клавиатура, работа с настоящим агентом.

Каждый сценарий: **что делаем → что должно получиться**. Если получилось не так, запишите номер сценария, что ожидали и что увидели (лучше со скриншотом).

## Подготовка

- Приложение запущено из этой ветки и перезапущено после изменений: менялось ядро.
- Есть папка, привязанная к каталогу с git-репозиторием, где есть ветка `dev`: так работает процесс «Разработка». Для остального хватит любой папки.
- Установлен хотя бы один агент: Claude Code или Codex. Для сценария 3.4 нужен агент без режима «без терминала» (или временно другой в настройке «Agent for changing processes»).
- Для сценария 8.4 нужен `gh` с доступом к репозиторию приложения. Этот сценарий создаёт **настоящий публичный issue**.
- Язык интерфейса русский. Проверьте ещё раз в английском (язык браузера `en`): все тексты должны быть на одном языке, без смеси.
- Свои процессы и версии записываются файлами в `plugins/my-processes/` рабочей копии. После проверки их нужно убрать (раздел «Уборка»).

## 1. Прочитать

**1.1. Каталог.** Под деревом нажмите «Процессы».
→ Карточки «Разработка», «Задача агенту», «Быстрая заметка». На каждой: что делает процесс, «N шагов · спросит вас N раз», где используется. Справа «Шаблоны для начала».

**1.2. Поиск и фильтры.** Наберите в поиске «тест», затем переключите «Мои», «Из плагинов», «С проблемами».
→ По «тест» находится «Разработка» (у неё есть шаг «Тесты»). Фильтры меняют список. Если ничего не найдено, написано «Ничего не найдено», а не пустой экран.

**1.3. Рецепт.** Откройте «Разработку».
→ 11 пронумерованных шагов в группах по статусам («К работе», «В работе», «Тестирование», «Проверка», «Вливается»). У каждого шага иконка того, кто делает: человек — вы, бот — агент. Шаги, где ждут вас, подсвечены. Под ветвящимися шагами написано, куда они ведут: «прошли → 8 · иначе ↩ 5», возвраты жёлтые. Внизу «Конец: статус «В dev»» и «Где используется».

**1.4. Карточка шага.** Нажмите шаг 7 «Тесты».
→ Справа карточка: кто делает, о чём спрашивает (с пометкой «только после нескольких неудачных запусков подряд»), «Команда тестов: как в настройках: pnpm test», статус, «Дальше». Под «Ещё» — что шаг получает и отдаёт, словами, без ключей. Клавиши ↑/↓ ходят по шагам, Enter открывает карточку.

**1.5. Задача по процессу.** В папке нажмите кнопку «Разработки», создайте задачу.
→ Полоса процесса на задаче: «Разработка · шаг 1 из 11», вопрос по-русски. Справа две кнопки: список (рецепт) и «…».

**1.6. Почему задача здесь.** Ответьте на первый вопрос, дождитесь следующего, затем «…» → «Почему задача здесь?».
→ Список пройденных шагов с итогом каждого («сделано», «вы ответили…», «ждёт вашего ответа») и временем. «Рецепт процесса» открывает рецепт, задача отмечена на своём шаге.

**1.7. Подсказки на кнопках папки.** Наведите курсор на кнопку процесса в строке папки. Откройте меню папки → «Другой процесс…».
→ В подсказке название, описание и «спросит вас N раз». В окне «Другой процесс…» у каждого процесса то же самое, шаблонов там нет.

## 2. Настроить

**2.1. Режим правки.** На странице «Разработки» нажмите `E` (или «Изменить»).
→ Кнопка становится «Готово», карточка шага превращается в форму.

**2.2. Параметр из настроек.** В шаге «Тесты» впишите в «Команда тестов» `npm run test:ci`.
→ Над рецептом полоса «Черновик · 1 изменение», у шага 7 метка «~», в строке рецепта видна новая команда. Стрелка у поля возвращает «как в настройках».

**2.3. Отмена.** Нажмите `Ctrl+Z` вне поля ввода, затем `Ctrl+Shift+Z`.
→ Изменение уходит и возвращается. «Отменить всё» убирает черновик целиком.

**2.4. Черновик переживает уход.** Поменяйте что-нибудь, уйдите на задачу, вернитесь.
→ Страница открывается в режиме правки, черновик на месте.

**2.5. Применить как свою версию.** Нажмите `Ctrl+Enter`.
→ Окно «Применить изменения?»: где используется, сколько задач идёт («закончат по старой версии»), что ваша версия встанет вместо процесса плагина. Впишите, что поменяли, нажмите «Применить». На карточке и в шапке появится «изменён вами», рядом «Сравнить с исходным».

**2.6. Сравнение и возврат.** Нажмите «Сравнить с исходным».
→ Один рецепт с пометками: «+» добавлено, «~» изменено, зачёркнуто убрано. «Вернуть исходный» с подтверждением возвращает процесс плагина.

**2.7. История.** Вкладка «История».
→ Версии с датой, «ваша / из плагина», заметкой и «сейчас» у текущей. «Сравнить» показывает разницу, «Вернуть» кладёт старую версию в черновик.

**2.8. Задача на старой версии.** Задача из 1.5, затем примените любую правку «Разработки».
→ На полосе задачи «процесс изменён». По клику видно, что изменилось, и есть кнопка «Перевести задачу на новую версию».

## 3. Изменить словами

**3.1. Поле.** На странице процесса нажмите `/`.
→ Курсор в поле «Что поменять?».

**3.2. Правка словами.** Напишите «не спрашивай перед мёржем, если тесты прошли», Enter.
→ «Агент меняет процесс…» с таймером, потом «Агент предлагает:» — рецепт с пометками и пара фраз о том, как агент понял просьбу. Ничего не применено, пока вы не нажали «В черновик». После «В черновик» включается режим правки, дальше всё как в 2.5.

**3.3. Уточнение.** Пока предложение на экране, допишите в поле «нет, только для папки …», Enter.
→ Новое предложение с учётом уточнения.

**3.4. Агент без режима без терминала.** Выберите такого агента в настройке «Agent for changing processes» и повторите 3.2.
→ Работает так же. Появляется «Показать терминал». Если агент просит разрешения, видно «Агент просит разрешения…» с кнопкой «Открыть терминал». После ответа один раз появляется предложение использовать агента без терминала («Не сейчас», «Больше не предлагать»).

**3.5. Тишина и таймаут.** Попросите что-то долгое или остановите агента в терминале.
→ Через минуту тишины «Агент давно молчит» с «Подождать ещё 5 минут» и «Остановить». Через 5 минут «Агент не ответил вовремя» и «Что он успел».

**3.6. С задачи.** На задаче «…» → «Изменить этот шаг словами».
→ Открывается рецепт, в поле подсказка «Что поменять в шаге N «…»?», курсор в поле.

**3.7. Без агента.** Если можно, проверьте на установке без агентов.
→ Вместо поля «Чтобы менять процесс словами, нужен агент» и «Выбрать агента».

## 4. Собрать свой

**4.1. Новый пустой.** «Процессы» → «Новый» → «Начать с пустого процесса» → введите название.
→ Пустой процесс в режиме правки: «Шагов пока нет» и три частых шага кнопками.

**4.2. Добавить шаги.** Нажмите «Спросить меня», потом «Добавить шаг» → найдите «команд» → «Команда».
→ Два шага с метками «+». У «Спросить меня» по-русски «Готово?» и ответы «Готово / Ещё раз».

**4.3. Плюс между шагами.** Наведите курсор между шагами.
→ Появляется «+»: окно выбора с подписью «Перед шагом N». Insert на выбранном шаге делает то же.

**4.4. Переставить, копировать, убрать.** Выберите шаг: «Выше», «Ниже» (`Alt+↑/↓`), «Дублировать», «Убрать» (`Del`).
→ Рецепт меняется, после «Убрать» тост «… убран · Отменить».

**4.5. Развилка.** В карточке «Спросить меня» → «Развилка по… → результату: Готово / Ещё раз», для «Ещё раз» выберите шаг выше.
→ Под шагом «Готово → … · Ещё раз ↩ N». «Один путь, без развилки» возвращает как было.

**4.6. Проблема с подсказкой.** Соберите процесс, где шагу чего-то не хватает: поставьте «Тесты на dev» из «Разработки» в пустой процесс.
→ В выборе шага он серый с причиной «не хватает: …». Если всё-таки попал в процесс: красный блок «Почему не может запуститься» с текстом проблемы и, где можно, кнопкой «Добавить «…» перед ним».

**4.7. Шаблон.** «Новый» → «Агент и моя проверка».
→ Копия-«ваш» процесс по-русски («Я проверяю», «Готово?», «Готово / Ещё раз»), открыт в режиме правки.

**4.8. Описать словами.** «Описать словами» в каталоге → «агент собирает материалы по теме, пишет черновик, я правлю».
→ Создаётся процесс с названием из первых слов, агент сразу начинает его собирать (дальше как в 3.2).

**4.9. Пробный запуск.** Примените собранный процесс, «Пробный запуск», оставьте «Без последствий», «Запустить».
→ Вкладка «Пробы»: задача пробы с её панелью, вопрос «Готово?», справа «Что получил и отдал каждый шаг». **В дереве этой задачи нет**, в поиске (`Ctrl+K`) тоже. Шаги с последствиями отмечены «пропущен: проба без последствий».

**4.10. По шагу.** Ещё проба с «По шагу».
→ Перед каждым шагом вопрос «Дальше: <шаг>» с «Выполнить / Пропустить / Остановить пробу».

**4.11. Запустить по-настоящему.** «Добавить кнопку в папку…» и «Создать задачу…» под «Где используется».
→ Кнопка появляется у папки (если кнопок уже пять, окно предупреждает про «Другой процесс…»). Задача создаётся и открывается.

## 5. Процесс внутри процесса

**5.1. Процесс как шаг.** В своём процессе «Добавить шаг» → найдите другой свой процесс (группа «Процессы», «весь процесс как один шаг · шагов: N»).
→ Строка «<процесс> · шагов: N ▸». Клик по «шагов» раскрывает его шаги серым («2.1», «2.2»). В сводке «спросит вас N раз (M — внутри «…»)».

**5.2. Карточка.** Откройте этот шаг в режиме правки.
→ Ссылка на процесс, «Что получает» (выбор из того, что есть до него), «Что отдаёт обратно», «Всегда актуальный / Своя копия». При «Своей копии» в рецепте пометка «(копия)».

**5.3. Используется внутри.** Откройте вложенный процесс.
→ Плашка «Этот процесс работает внутри: … Изменения здесь затронут и их.»

**5.4. Вынести.** В режиме правки выделите два соседних шага Shift+кликом → «Вынести в отдельный процесс» → название.
→ На их месте один шаг-процесс, новый процесс есть в каталоге. Для шагов не подряд — понятный отказ.

**5.5. На задаче.** Пройдите вложенный вопрос пробой или задачей.
→ Полоса: «Внешний › Внутренний · шаг N из M», вопрос внутреннего процесса.

## 6. Автоматизации

**6.1. Из процесса.** На «Разработке» «Запускать автоматически…» → папка → «Дальше».
→ Окно новой автоматизации с выбранным процессом. «Что дать процессу» — поле первой формы («Своими словами», подсказка «как описание задачи»). «Когда процесс спросит вас» — все вопросы по порядку с номерами шагов. Первый «заполнено выше: не спросит», редкие помечены «спрашивает только иногда».

**6.2. Ответ за вас.** Для «Разработка и автотесты завершены…» выберите «Отвечать «Готово к выкладке»», затем «если Тесты: прошли».
→ «Что вы найдёте» меняется: «пройдёт сама…» вместо «будет ждать вас на шаге 8».

**6.3. Вебхук.** Переключите на вебхук, сохраните, отправьте тестовый `curl` со страницы автоматизации, откройте её снова.
→ Под шаблонами виден последний запрос, клик по полю вставляет `{{payload.…}}` в поле, где был курсор.

**6.4. Новый вопрос.** Добавьте в «Разработку» (своя версия) шаг «Спросить меня» и примените. Откройте автоматизацию.
→ Жёлтая плашка «В процессе новый вопрос на шаге N…» с «Решить». В окне у вопроса метка «новый». Пока не решите, задачи ждут вас.

## 7. Новые шаги

**7.1. Шаг словами.** «Процессы» → «Шаги» → «Новый шаг словами»: «Написать changelog», задание, «быстро, одним ответом».
→ Кнопки «Вставить» вставляют `{{…}}` в текст. «Попробовать на задаче» показывает ответ агента, не трогая задачу. «Создать шаг» — шаг появился в «Мои/Агент» и в выборе шага.

**7.2. Шаг с выбором.** Тот же шаг с «Выбор из вариантов: ok, нужна правка», поставьте его в процесс.
→ В карточке есть развилка «результату: ok / нужна правка».

**7.3. Шаг в терминале.** Шаг словами «в терминале задачи…», пробный запуск.
→ Агент получает задание в терминале задачи. После `pitwall finished` процесс идёт дальше, или нажмите «Агент закончил».

**7.4. Шаг с кодом.** В выборе шага «Попросить агента сделать шаг» → опишите → «Начать».
→ Создаётся задача «Новый шаг» в папке приложения, в процессе на месте шага заглушка «Шаг делается»: процесс не может запуститься, в карточке «Открыть задачу» и «Поставить готовый шаг». Когда задача закончится, тост просит перезапустить приложение.

**7.5. Библиотека.** Вкладка «Шаги».
→ Все шаги по группам («Вы», «Агент», …), у каждого «процессов: N». Клик раскрывает, что шаг получает и отдаёт и где стоит. У своих шагов «Изменить» и «Удалить» (используемый удалить нельзя, с объяснением).

## 8. Полировка

**8.1. Схема.** На широком экране вкладка «Схема» у «Разработки».
→ Граф сверху вниз: возвраты жёлтыми линиями слева, пропуски справа, подписи ответов по-русски, шаги с вами обведены. Клик по шагу открывает рецепт с его карточкой. На узком окне вкладки нет.

**8.2. Привычка.** В настройках поставьте «Offer not to ask after, same answers» = 2. Два раза подряд ответьте на один вопрос одинаково (задачами или пробами).
→ На третий раз под вопросом «Вы раз за разом отвечаете «…»… Не спрашивать больше?». «Да» открывает «Что поменять?» с готовой просьбой (ничего не меняется без вашего «В черновик» и «Применить»). «Нет, спрашивать» убирает подсказку навсегда.

**8.3. Исходный обновился.** Сделайте свою версию «Разработки» (2.5), затем поменяйте `plugins/dev-flow/processes/dev.json` (например, описание).
→ Без перезапуска на карточке и в шапке «исходный обновился». По клику видно, что изменилось в исходном. «Перенести в мою версию» запускает агента (как 3.2).

**8.4. Поделиться (создаёт настоящий issue).** Меню «…» своего процесса → «Предложить в общий репозиторий…» → чем хорош → «Создать issue».
→ Тост «Issue создано» со ссылкой, в issue процесс файлом. Без `gh` — понятная ошибка.

## Для всех экранов

- **Темы**: светлая и тёмная, без нечитаемых цветов.
- **Клавиатура**: `E`, `/`, `Ctrl+Z`, `Ctrl+Shift+Z`, `Ctrl+Enter`, `Insert`, `Del`, `Alt+↑/↓`, стрелки по рецепту. В полях ввода `E` и `Del` печатаются, а не действуют.
- **Длинные названия** процессов и шагов (60+ символов) не ломают карточки, рецепт и схему.
- **Узкое окно**: страницы редактора без горизонтальной прокрутки, карточка шага на весь экран. Известное ограничение: боковая панель ядра на телефоне не сворачивается, это было и до редактора.
- **Перезапуск приложения**: задача, ждущая ответа (в том числе внутри вложенного процесса), после перезапуска ждёт того же ответа. Черновик на месте.

## Уборка

- Удалите `plugins/my-processes/` (ваши процессы, версии и шаги словами), если они не нужны. Или закоммитьте то, что хотите оставить.
- Удалите тестовые автоматизации и задачи. Пробы удалятся сами через день.
- Верните настройки «Agent for changing processes» и «Offer not to ask after…».
- Закройте issue из 8.4, если он был пробным.
