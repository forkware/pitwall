# Voice input

## Intent

Fill forms by voice (issue #25). Every multiline text field gets a microphone. Where a standard speech service exists it is used: the browser's Web Speech API on the web, the system dictation in the Mac window. Where none does (the Linux window, Firefox), speech is recognized by Whisper on the app's machine, phrase by phrase as the user speaks (issue #35, like WhisperWriter's continuous mode), a phrase in about 2 s after its pause (issue #50: a fast model kept loaded); if Whisper is not installed, the microphone asks first, and on "Fix" starts "Customize the app" with an agent asked to install it.

## Spec

- The core part: `<TextArea>` (`src/ui/TextArea.tsx`, in `#sdk/ui`) draws the `field.actions` slot in the field's corner and hands it a `FieldHandle` (`element()`, `insert(text)`, `focus()`). `insert` types at the cursor so that React's `onChange` and undo see it, with a space before when needed. Multiline fields of process forms use it.
- The desktop window has a preload (`src/desktop/preload.cjs`): `window.pitwallDesktop = { platform, startDictation() }`. `startDictation` sends `startDictation:` to the first responder on macOS (the same as Edit > Start Dictation or Fn Fn) and returns false elsewhere.
- The way, chosen per press (`speech.ts`, `chooseMethod`):
  - Mac window: focus the field and start macOS dictation; the system types into the field.
  - Windows window: focus the field and say "Press Win+H"; Windows' voice typing cannot be started by an app.
  - A browser with Web Speech (Chrome, Edge, Safari): recognition until pressed again or silence; final phrases go into the field. It is free, but the browser sends the audio to its vendor (Google, Microsoft, Apple). If it cannot reach its service (`network` error, as in Brave), Whisper from then on.
  - Otherwise (Linux window, Firefox): `rpc("voice-input", "status")`. When Whisper is there, record until pressed again: an AudioWorklet (`voice-input-tap`, from a Blob URL) mixes the microphone to mono and hands it to `PhraseSplitter` (`speech.ts`), which ends a phrase at a 900 ms pause (speech: a 30 ms frame 2.5 times louder than the quietest frame of the last 3 s and above 0.01 RMS; 300 ms of quiet kept around it; less than 200 ms of sound dropped; cut at 25 s without a pause). Each phrase becomes 16 kHz mono WAV (`downsample`, `encodeWav`) and goes to `rpc("voice-input", "transcribe", { audio, detected })` at once, one at a time, so earlier phrases are recognized while the user speaks on; texts are inserted in order. On the second press the last phrase goes too, and the spinner shows until all are in; "No speech recognized" if none had text. When it is not, show a dialog first (issue #34): speech recognition is not set up, an agent can install it, with "Fix" and "Cancel". "Fix" starts `rpc("customize-app", "start", { title, request })` with the install request from `status` and opens that task; "Cancel" or closing the dialog starts nothing (`offerInstall` in `speech.ts`).
- Whisper (`whisper.ts`): whisper.cpp (`whisper-cli`, `whisper-cpp`, `whisper.cpp` in PATH or `~/.local/bin`, with a `ggml-*.bin` from `~/.local/share/whisper.cpp/models` and other usual places) or openai-whisper (`whisper`, model `small`). Which model, by the setting `voice-input.speed` (issue #50): "fast" (default) prefers small, then base, medium, large-v3-turbo; "accurate" large-v3-turbo, then medium, small; an English-only `.en` model comes after the multilingual one of its size. Looked up on every press, so installing it needs no restart. `[BLANK_AUDIO]`-like marks are dropped. whisper.cpp gets all cores (`-t`) and, for a clip under 28 s, an audio context sized to it (`audioContext`: 50 frames a second plus 128, rounded up to 64, at least 512, since below that it repeats itself): its encoder otherwise works on 30 s whatever the clip, which made a 3 s phrase take as long as 30 s. With language "auto", whisper.cpp runs its encoder a second time to detect it (and whisper-cli on the full 30 s window, whatever `-ac`), so `transcribe` returns the detected language and the page sends it back as `detected` for the rest of the dictation; the setting, when not "auto", wins.
- The model kept loaded (`whisper-server.ts`, issue #50): when `whisper-server` lies next to the `whisper-cli` found (the same build) and `voice-input.keepLoaded` is on (default), phrases go to it instead of a new `whisper-cli` each: `whisper-server -m <model> -t <cores> --host 127.0.0.1 --port <free> -nlp`, `POST /inference` with the WAV, `language`, `audio_ctx`, `response_format=verbose_json` (it gives the detected language as a name, "russian", which whisper.cpp takes back as well as "ru"). `status` (the microphone's press) starts it, so the model loads while the user starts speaking; once up, it recognizes a second of quiet in English, because whisper.cpp detects a language with the window of the phrase before (the full 30 s on a fresh start). One server at a time: another model or command restarts it; it stops after 10 minutes without a phrase and on `app.stopping`; its pid is in `kv` so that one left by a crash is stopped at the next start. If it cannot start or answer, the phrase goes to `whisper-cli`, and a server that failed to start is not tried again for 10 minutes.
- Settings: `voice-input.language` (default "auto": Whisper detects it, the browser takes the page's language), `voice-input.whisperCommand`, `voice-input.whisperModel` (a path wins over `speed`), `voice-input.speed` ("fast" / "accurate"), `voice-input.keepLoaded` (default on).
- Recommended install: whisper.cpp's `whisper-cli` and `whisper-server` in `~/.local/bin` with `ggml-small-q5_1.bin` (190 MB) or `ggml-small.bin`; `large-v3-turbo` is better and about five times slower on a CPU.
- Measured (issue #50) on an i5-12450H in its power-saver profile, a 4.6 s phrase (the start of whisper.cpp's `samples/jfk.wav`), the time from sending the phrase to its text, with other work on the machine (single runs vary up to twofold under load):

  | | first phrase, "auto" | next phrases |
  |---|---|---|
  | before: large-v3-turbo q5_0, whisper-cli per phrase | 43 s | 11 s |
  | large-v3-turbo q5_0, whisper-server ("accurate") | 27 s (model still loading), then ~12 s | 10 s |
  | small q5_1, whisper-cli per phrase | 8.3 s | 2.8 s |
  | after: small q5_1, whisper-server (default) | 3.8 s | 2.0 s |
  | base q5_1, whisper-cli (wrong words: "ask NOTH!") | | 1.0 s |

  Where the time goes for whisper-cli: loading the model 0.3 s (small) to 0.6–1.3 s (turbo) and starting the process, the encoder almost all the rest (turbo 10–26 s a pass, small ~2 s), decoding 0.5–1.8 s; "auto" adds a full-window encoder pass (turbo +30 s, small +5 s), only +1.8 s on the warmed server. More threads than cores do not help (8 and 12 the same). It was ~45 s a press before #35.

## Check

`pnpm test` runs `tests/voice-input.test.ts`: finding whisper.cpp, its model (fast or accurate, multilingual first), whisper-server next to it, openai-whisper and the settings' paths; with a fake whisper-server: one start for many phrases, the warm-up, the detected language's name, another model restarting it, stopping when unused, a server that cannot start failing fast and not being started again, the plugin falling back to whisper-cli when it fails or `keepLoaded` is off; running both kinds on a WAV with fake commands, the threads, the audio context and the detected language; the language the server passes (detected only under "auto"); splitting into phrases (a pause ends one, a breath does not, clicks and a steady hum are not speech, speech right after the press is, long speech is cut) and downsampling; the install request when Whisper is missing; no agent unless the user picks Fix; the choice of the way; the WAV encoding. By hand: in Chrome, open a process form with a multiline field, press the microphone, speak, press it again: the text is in the field. In the Linux window without Whisper, the microphone shows the dialog; Cancel closes it and no task appears; Fix opens a Customize the app task whose agent installs Whisper; after that, the microphone records and the text of each phrase appears a few seconds after a pause, while recording goes on. With whisper-server and a small model (after a server restart), the text appears about 2 s after a pause, the first phrase about 4 s; `pgrep -a whisper-server` shows one server while dictating and none 10 minutes later or after the app stops. Speed "Accurate" in the settings switches to large-v3-turbo (the next phrase restarts the server with it). On a Mac, the microphone starts the system dictation.
